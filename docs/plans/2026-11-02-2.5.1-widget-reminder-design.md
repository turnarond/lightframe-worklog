# 2.5.1 设计稿：提醒节奏 + 挂件壁纸态

> 分支策略：从 `baseline/v2.5.0-snapshot` 切出 `release/2.5.1`。`feat/v3.0-cloud` 继续只做 v3.0。
> 代价：本分支会包含 v3.0 已改的核心文件（`src/store.js`、`src/renderer.js`、`src/sync*.js` 等），因当初无干净的 2.5.0 基线。这是已知且可接受的技术债，待有发布产物时再重建纯净 2.5.0 线。

## 目标（用户原话）
1. 右下角「每日待办」系统通知太频繁 → 改为 **17:00 起每小时一次**，22:00 后停止。
2. 右上角两个按钮：鼠标穿透失效、面板不够透明不像桌面背景、展开/收起只缩内容不缩窗口。
   → 收起态做成**半透明壁纸态**：默认更透（~0.55）、真正鼠标穿透（仅手柄可拖/点）、窗口按内容自适应高度。

## 一、提醒合并（问题1，`main.js`）

删除现有两套独立提醒（日报 `17:30`、到期 `09:00`），合并为单条「每日待办」。

- 触发窗口：`17:00 ≤ 当前小时 < 22:00`（即 17:00–21:59）。
- 去重键：`日期 + 小时`（如 `2026-11-02-17`）。配合现有 `REMINDER_INTERVAL = 60s` 轮询，天然实现「每小时一次」且不重复。
- 触发内容条件：以下任一为真才弹通知
  - 今日有到期任务（`dueDate === today`）
  - 有逾期任务（`dueDate < today` 且未完成）
  - 日报未写（`logsCache[today]` 的 progress/issues/plan 全空）
- 文案示例：`今日到期 2 项（高优 1），逾期 3 项；日报还没写`
- 停止：`hour >= 22` 后不再弹（无需写标记，次日 0 点后日期变化，键自然失效）。
- 已彻底移除 `dailyReminder` / `dueReminder` 设置项及其 UI；`settings.lastReminded` 仅保留 `todoHour`（按「日期 + 小时」去重），旧的 `daily` / `due` 字段不再写入默认值。

## 二、真·鼠标穿透（问题2a，`main.js` + 渲染端）

现状：渲染端只切了 CSS `body.ct-mode`（`pointer-events:none`），但**主进程从未调用 `setIgnoreMouseEvents`**，所以操作系统层面窗口仍吃点击，穿透无效。

- 主进程新增 IPC `widget:setClickThrough(flag)`：
  `mainWindow.setIgnoreMouseEvents(flag, { forward: true })`。
- 渲染端 `toggleClickThrough`：在切 `ct-mode` 的同时调用 `bridge.setClickThrough(next)`（与 `setWidgetExpanded` 同模式，补 preload 方法）。
- `forward: true` 让页面仍收到鼠标事件：渲染端监听 `document` 的 `mousemove`，若命中手柄/按钮/弹窗（`closest('.w-handle, button, .modal, input, textarea')`）则临时 `setClickThrough(false)`，否则 `setClickThrough(true)`。节流（~50ms）避免 IPC 抖动。
- 效果：穿透态下正文点击「穿过」窗口落到桌面；仅手柄可拖、按钮可点。展开面板时 `clickThrough` 自动置 false（沿用现有 `toggleExpand` 逻辑）。

## 三、半透明壁纸态（问题2b，`src/store.js` + `src/styles.css`）

- 默认 `widget.opacity`：`0.9` → `0.55`（桌面透出，像背景）。`blur` 维持（Windows 透明窗口下 `backdrop-filter` 无法采样桌面，近似无效但无害）。
- `body::before` 噪点叠层 `opacity .42` 调淡至 `.28`，降低「纸张感」、更像壁纸。
- `body` 背景 `rgba(243,236,224, var(--w-opacity))` 不变，靠变量调；`--w-opacity` 仍由 `applyWidgetStyle` 注入。
- 同步更新 `src/store.js` 默认值与 `src/store.test.js` 期望值。

## 四、收起态自适应高度（问题2c，`main.js` + 渲染端）

现状：`widget:setExpanded` 用 `setSize` 但窗口 `resizable:false`；收起固定高 560，`.w-body{flex:1}` 把日历顶到底，中间留空白 → 看起来「面板还是这么大」。

- 渲染端每次 `renderWidget` 后量出内容高度：手柄 + 正文(w-body) +（面板展开时）面板 之和，夹紧 `[360, 820]`，通过新 IPC `widget:setHeight(h)` 告知主进程。
- 主进程 `widget:setHeight`：`mainWindow.setResizable(true)` → `setSize(420, h, false)` → `setResizable(false)`，绕过 `resizable:false` 限制。
- 展开态同样走自适应（量面板内容高度），不再用固定 820。
- 宽度保持 420 固定；位置由现有 `moved` 监听继续保存 x/y。
- `flex:1` 的留白因窗口高度＝内容高度而自然消失。

## 涉及文件
- `main.js`：`checkReminders` 重写、新增 `widget:setClickThrough` / `widget:setHeight` IPC。
- `src/renderer.js`：`toggleClickThrough` 调 IPC + `mousemove` 穿透切换；`renderWidget` 末调用 `resizeToContent()`。
- `preload.js`：暴露 `setClickThrough`、`setHeight`。
- `src/store.js` / `src/store.test.js`：`widget.opacity` 默认 0.55。
- `src/styles.css`：`body` 噪点 `opacity` 调淡。
- `package.json`：版本 `2.5.0` → `2.5.1`。

## 测试计划

- 手动/集成（本机无 GUI，靠 dev 脚本或用户验收）：
  - 17:00–21:59 每小时弹一次合并通知；22:00 后不弹；改系统时间验证去重。
  - 点穿透按钮后，正文区点击「穿过」到桌面，手柄可拖、按钮可点；移开恢复。
  - 收起态透明度明显变低、像桌面背景；任务少时窗口小巧、无大片空白。
  - 展开/收起窗口高度贴合内容。
