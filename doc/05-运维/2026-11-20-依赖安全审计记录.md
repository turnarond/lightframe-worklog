# 依赖安全审计记录（2026-11-20）

> 触发：v2.8.0 收口执行 `npm ci` 后由 npm 自动报告。
> 结论：**本版本不夹带依赖升级**；升级单独立项，完成回归后再发新版。

## 二、风险评估

- `electron` 的高危项影响已打包应用（ASAR 完整性绕过），是本批最需要优先处理的一项。
- critical `tar` 与其余 high/moderate 均位于构建链，不进入最终运行时，但会污染构建机与发布产物。
- 当前未发现 `electron-updater` 的告警；后续升级构建链时仍需回归自动更新链路。

## 三、后续动作（规则 10 闭环）

1. 单开 `fix/deps-security` 分支升级 Electron 与 electron-builder；禁止 `npm audit fix --force` 直接改主分支。
2. 升级后重跑 `npm test`、UI 烟测、`verify-lan --self-host`、打包与 `release_gate.py`。
3. 在 GitHub 仓库登记 Issue，完成前本记录保持为未决项；不得声称「依赖已安全」。
