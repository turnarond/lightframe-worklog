## 问题与影响

发布脚本 `scripts/release.js` 在更新下载验证之前就打印 `git push` / `git tag` /
`gh release create` 命令。若更新验证随后失败，操作者可能已按提示执行推送与发布，
把未通过验证的产物发出去。最终评审（会话 `fb0863fa`）将其列为 N1 阻断项。

同时，README 的安装校验区块仍停留在 v2.11.1 的文件名与 SHA-256，与 2.12.0 安装包
不一致，下载者按该哈希校验必然失败（I2）。

## 设计决策

- `collectMaterials` 只负责落盘与对账，返回材料清单，不再打印发布命令。
- 发布命令统一在 `verifyUpdate` 成功之后（或显式 `--skip-update`）打印；任一步失败时
  流程在打印前退出，不出现推送/发布提示。
- 新增 `scripts/release-order.test.js`：以源码顺序断言命令打印位于 `verifyUpdate` 之后，
  且 `collectMaterials` 内不得出现发布命令。
- README 安装校验区块在真实 2.12.0 安装包构建完成后，按实际文件名、大小与 SHA-256 回填；
  该动作写入发布检查单硬性项，避免再次出现版本漂移。
