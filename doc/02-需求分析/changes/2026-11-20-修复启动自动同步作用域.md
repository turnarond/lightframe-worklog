## 问题与影响

- 实测启动日志：`[boot] 启动失败： ReferenceError: runSync is not defined`（`main.js:692`）。
- 根因：`runSync` 与 `updateLastSyncAt` 定义在 `registerIpc()` 内部，`bootstrap()` 在函数外部
  用 `setTimeout(runSync, 2000)` / `setInterval(runSync, 30000)` 引用，取不到标识符。
- 影响：应用启动后**自动同步定时器从未建立**；已配置同步码的用户只能手动点「立即同步」，
  「启动补一次 + 30s 周期同步」的同步可信度能力实际失效。窗口与其余功能不受影响，故易被漏测。

## 设计决策

- 将 `updateLastSyncAt` 与 `runSync` 从 `registerIpc()` 内部移到模块作用域；IPC 处理器与
  `bootstrap` 共用同一函数。两者只依赖模块级 `syncBridge` / `settings` / `syncMetaStore` /
  `net` / `sendToMain`，移动不改变行为。
- 备选：在 `bootstrap` 内通过回调引用 IPC 内函数——增加隐式状态，不采用。
- 新增 `tools/smoke-boot.js`：用独立临时 userData 启动真实 Electron，抓取 stdout/stderr，
  断言无 `[boot] 启动失败` 且页面 ready；接入 `npm run smoke:boot`。

## 验收判据

- 修复前：`node tools/smoke-boot.js` 失败，输出含 `ReferenceError: runSync is not defined`（RED）。
- 修复后：同一命令通过，启动日志无 `[boot] 启动失败`，页面 ready（GREEN）。
- `npm test` 151/151、逐文件 `node --check`、`verify-lan --self-host` 不回归。

## 风险

- 启动烟测需要本机 Electron 二进制；无二进制环境会报错而非静默跳过。
- 该烟测只覆盖启动期异常，不覆盖真实同步网络往返（由 `verify-lan` 覆盖）。
- 修复后仍需观察：已配置同步码的场景下 30s 定时器是否持续运行（本轮以代码审读 + 启动日志确认）。
