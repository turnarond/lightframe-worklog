## 问题与影响

- v2.8.1 目前只有源码 tag，没有 GitHub Release；自动更新源是 GitHub Releases，
  已安装 v2.8.0 的用户拿不到启动同步修复。
- 需要产出 NSIS 安装包、blockmap 与 latest.yml，并校验资产名/哈希与 updater 元数据一致。
- 独立评审实跑 `npm run smoke` 5 次出现 2 次失败：`Page.reload` 后等待条件会被旧文档满足，
  固定 600ms 又可能短于新文档首屏 `ready`，发布验证不可复现。

## 设计决策

- 使用已构建的 `dist/win-unpacked` 与 NSIS 安装包，不重新改代码。
- electron-builder 生成的 `latest.yml` 指向安全文件名 `lightframe-worklog-setup-2.8.1.exe`；
  本机产物为中文名，发布前复制为同名安全文件，使 GitHub 资产名、URL 与 latest.yml 完全一致。
- 用 `gh release create v2.8.1` 上传安装包、blockmap、latest.yml；tag 已存在，不重建 tag。
- 不修改已发布 tag 指向的代码；发布记录作为后续文档提交。
- 烟测修复：`Page.addScriptToEvaluateOnNewDocument` 注入唯一 `__smokeDocToken`，
  `Page.reload` 后轮询「新文档 token + `body.ready`」最多 10s；不再依赖旧文档的 `#cat-chips` 或固定 sleep。
- 仓库可见性：已由 private 改为 public（用户授权），匿名 API 200，满足 electron-updater 匿名下载前提。
