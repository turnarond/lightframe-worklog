# Change Card: 2026-11-21-CI自动化门禁

- 日期: 2026-11-21
- 负责人: 闫朝东（AI 代理执行）
- TDD 深度: tdd:免（理由：仅新增 CI 配置与本地打包脚本，不改业务源码；以既有 151 项测试、烟测与工作流 YAML 校验为证据）
- 基线冻结: 不适用：不编辑业务源码与测试断言

## 问题与影响

- 当前所有门禁依赖本地手工执行；干净构建纪律（Electron 包/二进制一致）没有机械防线。
- 依赖审计、语法、启动烟测、打包版 UI 烟测容易漏跑；PR/合入没有统一状态。
- 需要在 GitHub 上固化 Windows 门禁，减少“本地全绿、合并后出错”。

## 设计决策

- 新增 `.github/workflows/ci.yml`：`windows-latest` 单作业，Node 24。
- 触发：`push` 到 `main`、`v*` tag、`pull_request`、`workflow_dispatch`。
- 步骤顺序：
  1. `npm ci`（干净安装）
  2. 校验 `node_modules/electron/dist/version` 与包版本一致（防混合态）
  3. `npm test`（151 项）
  4. 逐文件 `node --check`
  5. `npm audit --audit-level=high`（只拦截 high/critical；6 项 dev-only moderate 不阻断）
  6. `npm run smoke:boot`
  7. `node tools/verify-lan.js --self-host`
  8. `npm run pack:dir`（只打包 payload，不构建 NSIS）
  9. 校验 `dist/win-unpacked/光影工作志.exe` 含 `Electron/<版本>` 串
  10. `npm run smoke`（打包版 UI 烟测）
- 新增 `pack:dir` 脚本，避免 CI 首次构建就下载 NSIS 工具链。
- CI 不发布 Release、不签名；发版仍走本地/干净 worktree + release_gate + 人工授权。

## 验收判据

- 本地等价命令全部通过（测试、语法、审计 high、启动烟测、局域网自测、pack:dir、打包版烟测）。
- 推送后 GitHub Actions `CI` 为绿色。
- CI 拦截条件正确：Electron 包/二进制不一致、high/critical 漏洞、测试/烟测失败均会红。

## 风险

- GitHub Windows runner 的 GUI 会话可能影响 Electron 打包版烟测；若失败需改为 `--disable-gpu` 或调整烟测。
- CI 首次运行需下载 Electron 45 与 npm 依赖，耗时约 5–10 分钟；未启用 Electron 缓存。
- `verify-lan --self-host` 依赖本机非 loopback IP 与端口；runner 防火墙策略可能影响。
- 审计阈值只拦截 high/critical；6 项 moderate 构建链漏洞不会让 CI 变红。
- 工作流存在不等于分支保护；需在 GitHub 设置 required status checks 才真正阻断合入。
