# 数据安全闭环（本地备份 / 恢复 / 导入导出）设计

- 版本：v2.11.0 设计稿
- 日期：2026-11-21
- 状态：待评审
- 上游：产品规格 §3 / §13、同步码设计与同步可信度设计
- 下游：实施计划（待设计评审通过后编写）

## 1. 背景与问题

当前数据保存在 Electron `userData` 的四个 JSON 文件中，写入使用 temp + rename 原子写。仍有两个缺口：

1. **没有本地历史版本**：误删、误改、同步覆盖后无法回到之前状态。
2. **损坏时静默降级**：读取层遇到 JSON 损坏会返回空数据，用户看到“数据没了”，且原文件可能被后续写入覆盖。

同步码方案已提供多设备同步，但 LWW 仍可能用旧数据覆盖新数据；服务端备份与冲突合并不在本期范围。

## 2. 目标与非目标

### 目标

- 每次写盘前自动生成**一致的本地恢复点**，保留最近 10 份 + 最近 7 天每日 1 份。
- 支持**整份快照恢复**：任务、日报、设置一次恢复；恢复前自动再备份当前状态。
- JSON 损坏时**不静默清空**，明确提示并引导恢复或导出原文件。
- 支持单文件导出 / 导入（`.lightframe-backup.json`），换机与归档可用。
- 恢复后暂停同步，避免把旧快照推回服务端。

### 非目标

- 不做按文件恢复、合并恢复（任务 id / 日志日期合并）。
- 不做服务端版本历史、服务端备份、冲突合并 UI；这些进入 v2.12.0。
- 不做账号体系、端到端加密、跨设备同步备份文件。
- 不改同步码协议与 LWW 合并规则。

## 3. 已确认的产品决策

| 决策 | 结论 |
|---|---|
| 目标用户 | 小范围朋友/同事 |
| 同步承载 | 由项目所有者统一托管一台同步服务 |
| 优先级 | 数据安全优先于功能扩展 |
| 备份触发 | 每次写盘前快照；按内容哈希去重；自动备份默认开启，可手动关闭 |

| 敏感字段 | 自动备份包含同步码/服务器地址；手动导出默认脱敏 |
| 恢复粒度 | 整份快照恢复；恢复前自动再做当前快照 |

## 4. 架构

### 4.1 模块边界

| 模块 | 职责 |
|---|---|
| `src/backup.js`（新增） | 备份集生成、列表、轮转、恢复、导入导出、哈希与校验；纯 Node，可单测 |
| `src/store.js` | 写盘前调用备份钩子；读取返回损坏状态 |
| `main.js` | 创建备份管理器；IPC：列表/立即备份/恢复/导出/导入/打开目录；恢复后暂停同步 |
| `src/renderer.js` + `index.html` + `styles.css` | 设置页「数据与备份」区块与确认流程 |

### 4.2 备份集

目录：`userData/backups/<YYYYMMDD-HHmmss-SSS>/`

每次写盘前，备份管理器读取当前四份文件，写入同一恢复点：

```
tasks.json
dailyLogs.json
settings.json
syncmeta.json
meta.json   // createdAt / appVersion / reason / 每文件 sha256+size / setHash
```

- 四份文件一次读取、一次写入，保证恢复点内部一致；`syncmeta.json` 仅用于诊断与导出，
  **恢复时只写回 tasks / dailyLogs / settings，syncmeta 不写回并清空游标**。
- `meta.json` 最后写入；缺少 `meta.json` 的目录视为未完成，列表忽略。
- 写入采用临时目录 + rename，避免半个恢复点。
- 备份失败（磁盘满/权限）时**中止本次业务写入**并提示用户，不产生“以为有备份、实际没有”的假安全。

### 4.3 触发与去重

- 所有业务写盘（任务、日志、设置、同步元数据）在 temp + rename 之前调用
  `backupManager.beforeWrite(reason)`。
- `beforeWrite` 读取四份当前文件，计算 `setHash`（各文件 sha256 拼接后再 sha256）。
- 与最近一个成功恢复点 `setHash` 相同则跳过，避免自动保存/同步写入造成重复。
- 备份管理器内部串行化（Promise 队列），避免并发写盘生成交叉恢复点。

### 4.4 保留策略

每次成功生成恢复点后执行轮转：

1. 按创建时间倒序，保留最近 **10** 份。
2. 再按本地日历日分组，保留最近 **7** 个自然日中每天的**最后一份**（最接近当天结束的状态）。
3. 合并集合，删除其余目录；最多约 17 份。
4. 删除失败只记录警告，不影响当前写入；下次轮转重试。

### 4.5 恢复

1. 用户在设置页选择恢复点，看到摘要：时间、任务数、日志天数、设置大小、是否含同步码。
2. 二次确认后，先生成 `reason=pre-restore` 的当前状态快照；失败则中止恢复。
3. 将恢复点的 tasks / dailyLogs / settings 写回（temp + rename）；`syncmeta` 不写回，直接清空游标；
   任一文件失败时，用 pre-restore 快照回滚已写文件。
4. 恢复后：
   - `settings.syncPaused` 置为 `true`；
   - `syncmeta.json` 保持空游标；
   - 重新加载渲染层；提示“已恢复，同步已暂停；确认数据后可在设置页恢复同步”。
5. 恢复同步时先做一次全量 pull，再允许 push；避免旧快照直接覆盖服务端。

### 4.6 损坏保护

- `store` 的读取增加 `loadWithStatus()`，返回 `{ data, corrupt, error }`；保留 `load()` 兼容旧调用。
- 任一文件 JSON 解析失败时：
  - 不覆盖原文件、不写入空数据；
  - 主进程记录损坏文件路径与时间（不记录内容）；
  - 首屏显示错误卡片，提供「从备份恢复」「导出损坏文件」；
  - **按文件隔离**：损坏文件对应的写入被阻止（例如 tasks 损坏则暂停任务写盘），
    `dailyLogs` / `settings` 等未损坏文件仍可正常使用；用户恢复或显式忽略后才解除。
- 备份列表在损坏状态下仍可用（备份目录独立于主数据文件）。

### 4.7 导出 / 导入

单文件格式：

```json
{
  "format": "lightframe-backup",
  "formatVersion": 1,
  "exportedAt": "2026-11-21T12:00:00.000Z",
  "appVersion": "2.11.0",
  "files": {
    "tasks": [],
    "dailyLogs": {},
    "settings": {},
    "syncmeta": {}
  },
  "checksums": { "tasks": "sha256...", "dailyLogs": "..." }
}
```

- 导出默认将 `settings.syncCode` 与 `settings.serverUrl` 置空；用户勾选「包含同步码」才保留。
- 导入先校验格式、版本、checksums；通过后展示摘要，再走与恢复相同的 pre-restore + 整份恢复流程。
- 导入失败不修改任何现有文件；错误信息标明字段/校验失败原因。

## 5. 数据流

```
业务写盘
  → backup.beforeWrite(reason)
     → 读取四份当前文件
     → setHash 去重
     → 写 backups/<id>/ + meta.json
     → 轮转 10+7
  → 原 temp + rename 写盘

恢复 / 导入
  → 校验恢复点或 bundle
  → 生成 pre-restore 快照
  → 写回四份文件（temp + rename，失败回滚）
  → syncPaused=true；syncmeta 清空
  → 重新加载 UI
```

## 6. UI

设置页新增「数据与备份」区块（放在「多设备同步」之后）：

- 顶部：自动备份开关（`settings.backup.enabled`，默认开）、保留策略说明、当前占用空间。
  关闭后仅保留「立即备份」，并在区块内明确提示“已关闭自动备份，误删可能无法恢复”。
- 恢复点列表：时间、任务数、日志天数、大小；操作「恢复」「导出」。
- 「立即备份」按钮。
- 「导入备份」按钮。
- 「打开备份目录」。
- 恢复确认弹窗：摘要 + “恢复后同步将暂停”提示 + 二次确认。
- 损坏状态：首屏错误卡片提供「从备份恢复」「导出原文件」。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 备份失败 | 中止业务写入，toast 明确原因；不更新内存中的“已保存”状态 |
| 备份目录不存在 | 自动创建；失败按备份失败处理 |
| 恢复点缺 meta / 文件不全 | 列表忽略；不提供恢复 |
| 恢复中途失败 | 用 pre-restore 快照回滚，提示恢复失败 |
| 导入校验失败 | 不写任何文件，展示失败原因 |
| 同步暂停期间 | `sync:status` 返回 `paused`；设置页显示“恢复同步”按钮 |

## 10. 验收判据

1. 写盘前生成恢复点；相同内容不重复生成；轮转符合 10+7。
2. 模拟 tasks.json 损坏：应用不静默清空，显示错误并可恢复。
3. 恢复整份快照成功；恢复前自动生成 pre-restore；恢复后同步暂停。
4. 导出默认脱敏，导入 roundtrip 可恢复；校验失败不修改现有数据。
5. 备份失败时业务写入不落盘，提示明确。
6. 151 项测试、启动烟测、打包版 UI 烟测全绿。

## 11. 风险与边界

- 自动备份含同步码：本地明文风险等同 `settings.json`；UI 明示，手动导出默认脱敏。
- 自动备份可被用户关闭；关闭后误删只能依赖手动备份或服务端数据，UI 必须持续提示。
- 磁盘占用：典型 JSON 小于 1 MB，最多约 17 组；设置页显示占用。
- 恢复旧数据可能与服务端新数据冲突：恢复后强制暂停同步，重新启用时全量 pull，避免直接覆盖。
- 损坏检测改变 store 读取语义：需要逐调用点迁移并补测试。
- 备份不替代服务端备份；统一托管服务端的每日备份进入 v2.12.0。
